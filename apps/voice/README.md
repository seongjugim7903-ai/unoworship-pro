# 우노워십 음성 자동 송출 모듈

설교 중 목사님이 호명하는 성경 구절을 음성으로 감지해
**자막 송출 이벤트를 발행하는 독립 모듈**입니다.

우노워십 프로(송출 프로그램)에 이벤트만 던지고, 화면을 직접 그리지 않습니다.
**이 모듈이 죽어도 수동 송출은 100% 정상 동작합니다.**

---

## 왜 필요한가 — 실측 근거

2026-07-26 예배 사고(1:01:35, 약 30초 중단) 이후 설교 3편을 음성 분석했습니다.

구절을 호명하고 **본문 낭독을 시작하기까지의 여유 시간**입니다.

| 설교 | 유형 | 평균 | 최단 |
|---|---|---|---|
| 2026-07-26 | 즉흥형 | 0.51초 | 0.25초 |
| 2026-07-12 | 원고형 (다른 설교자) | 0.49초 | 0.29초 |

사람이 "듣고 → 인지 → 검색 → 클릭"하려면 최소 1.5~2초가 필요합니다.

> **담당자의 숙련도 문제가 아니라, 물리적으로 불가능한 업무 설계였습니다.**
> 설교자를 바꿔도 0.5초는 그대로였습니다. 구조적 특성입니다.

## 동작 원리

```
발화 → 구어체 어댑터 → 문맥 추적 → 게이트 판정 → 이벤트
```

### 1. 구어체 어댑터
음성인식 출력을 표준 참조로 바꿉니다.

| 입력 | 결과 |
|---|---|
| `요한복음 13장 31절에서부터 38절` | jhn 13:31-38 |
| `시편 23편 3절` | psa 23:3 (시편만 '편' 사용) |
| `열왕기아 5장 9절` | 2ki 5:9 (**STT 오인식 자모 근사 매칭**) |
| `요한복음 아 고린도서 13장` | 1co 13 (자기정정) |

### 2. 문맥 추적 — 핵심
절 번호만 말씀하셔도 해석합니다. **본문이 미리 등록되어 있어야 가능합니다.**

```
"6절을 보세요"  →  (등록된 본문 요 5장)  →  요한복음 5:6
```

실제로 이찬수 목사님이 `본문`이라는 말 없이 절 번호만 말씀하신 **12건 전부** 정확히 해석했습니다.

### 3. 본문 ↔ 인용 혼선 방지
절 번호가 양쪽에 다 있을 때를 **등록된 범위로 구분**합니다.

```
본문  요 2:2-25      인용  마 13:7-13

"8절"        → 인용 범위 안        → 마 13:8
"20절"       → 인용 밖, 본문 안    → 요 2:20
"본문 8절"    → 본문 명시 우선       → 요 2:8
5분 뒤 "12절" → 시간 무관, 범위 안   → 마 13:12
```

### 4. 장 검색 모드
절 번호 없이 장만 말씀하시는 경우입니다. *(성경 데이터 필요)*

```
"요한복음 6장에 보면 이런 말씀 있습니다"   ← 장만 지목
        ↓ 이어지는 낭독을 대조
35절로 특정 → 자동 송출
```

1·2위 유사도가 비슷하면 **애매하다고 판단해 포기**합니다. 잡담에는 반응하지 않습니다.

### 5. 게이트 판정

| 조건 | 동작 |
|---|---|
| 책·장·절 완창 | `auto` — **인용 목록에 없어도 자동 송출** |
| 본문 범위 + 신호 표현 | `auto` |
| 그 외 확신도 0.6↑ | `hold` — 후보 제시 |
| 암송·필사 이야기 | 무시 (예화이지 송출 요청이 아님) |

## 운영 모델 — 자율주행

```
설교 시작 → [음성송출 버튼] → 자율주행 ON → 사람은 감시만
```

**선송출 후정정**입니다. 여유가 0.5초뿐이라 "물어보고 허가받는" 구조는 성립하지 않습니다.
자율주행차가 차선 변경 허가를 묻지 않는 것과 같습니다.

| 동작 | 주체 |
|---|---|
| 띄우기 | 기계 (0.5초, 사람은 불가능) |
| 바꾸기 | 기계 (다음 구절 = 자연 교체) |
| 되돌리기 | 숫자키 `1·2·3` |
| 취소 | `0` 또는 `ESC` |

확정 입력은 **숫자키**입니다. 마우스는 조준 동작 때문에 약 5배 느려 0.5초 안에 불가능합니다.
(`tools/reaction-test.html` 로 담당자 실제 반응속도 측정 가능)

## 우노워십 프로 연동

> 이 모듈은 `unoworship-pro/apps/voice/` 에 함께 관리됩니다.
> 아래 세 지점이 바뀌면 이 모듈도 같이 확인해야 합니다.
>
> | 우노워십 프로 | 이 모듈에서 맞물리는 곳 |
> |---|---|
> | `apps/atem-field/lib/socketEvents.ts` | 이벤트 타입 (아래 규격) |
> | `apps/atem-field/lib/bible/referenceParser.ts` | `src/parser/books.js` 의 bookId 체계 |
> | `data/bibles/local-bible.json` | `src/bible/localBibleSource.js` 의 데이터 형식 |

기존 Socket.IO 이벤트 계층에 **음성 전용 타입만 추가**합니다. 기존 타입은 건드리지 않습니다.

```ts
// apps/atem-field/lib/socketEvents.ts 에 추가
| { type: 'VOICE_DETECTED'; payload: {
      ref: { bookId: string; chapter: number; verses: number[] };
      display: string;          // "요한일서 5:3"
      confidence: number;
      action: 'auto' | 'hold';
      raw: string;              // STT 원문
      latencyMs: number;
  } }
| { type: 'VOICE_CORRECTED'; payload: { ref: object; display: string } }
| { type: 'VOICE_STATE'; payload: { state: 'idle'|'armed'|'preaching' } }
| { type: 'VOICE_HEARTBEAT'; payload: { ts: number; audioLevel: number } }
```

**중요**: 음성 모듈은 아웃풋에 직접 쏘지 않고 **반드시 컴포저를 거칩니다.**
자동과 수동이 같은 경로를 써야 상태가 갈라지지 않습니다. (핸들은 하나)

하트비트가 2초 이상 끊기면 컴포저가 자동으로 수동 모드로 전환합니다.

## 사용 예

```js
import { Detector } from './src/detect.js';
import { tryLoadBible } from './src/bible/localBibleSource.js';

const detector = new Detector({
  passage:   { bookId: 'jhn', chapter: 2, verses: [2,3,4,5,6,7,8,9,10] },
  quoteList: [{ bookId: 'mat', chapter: 13, verses: [7,8,9,10,11,12,13] }],
  bibleSource: tryLoadBible('/path/to/local-bible.json'),  // 없으면 null
});

// STT 결과가 올 때마다 호출 (텍스트, 시각(초))
const events = detector.feed('마태복음 13장 7절을 보십시오', 128.4);
for (const e of events) {
  if (e.action === 'auto') sendToComposer(e);
}
```

## 아직 안 되는 것 (정직하게)

- **출처 없는 암송** — 장절을 말하지 않고 구절만 외워 인용하는 경우. 1차 설교에서 3건 확인. 장 검색 모드를 전체 성경으로 확장해야 하는데 오검출 위험이 커서 보류
- **실제 음성 검증** — 지금까지는 전부 **텍스트 기준**입니다. 유튜브 자동자막이 구절 참조 29건을 전부 정확히 인식했다는 근거는 있지만, 예배당 실환경은 내일 측정해야 합니다
- **hold 비율** — 자동이 아닌 확인 대기가 설교당 7~12건입니다. 인용 목록에 절 범위까지 등록되면 줄어듭니다

```
✅ 마태복음 13:7-13    범위 있음 → 정확히 구분
⚠️ 마태복음 13장        장만 → 추정 폴백 (정확도 하락)
```
