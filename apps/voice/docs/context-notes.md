## 2026-07-28 — 맥미니 1·2단계

### 성경 데이터: 별도 설치 없이 기존 파일 재사용

`README` 는 `~/Library/Application Support/UnoWorship/data/bibles/local-bible.json` 을 가정하지만
그 경로는 이 맥에 없다. 대신 현장 운영 중인
`UnoLive-plus-atem-field/data/bibles/krv.json` 이 **형식이 정확히 일치**한다.

```
{ version, books: [ { num, id:'gen', name:'창세기', abbr, testament,
                      chapters: [ { num:1(int), verses: [ { num:1(int), text } ] } ] } ] }
```

`localBibleSource.js` 가 기대하는 `books[].id / chapters[].num / verses[].num` 이 전부 맞고
`chapters[].num`·`verses[].num` 이 **정수**라 `getChapter` 의 엄격 비교(`===`)도 통과한다.
→ 저작권 구조(교회가 보유한 데이터 참조)를 지키면서 데이터 중복 설치를 피한다.

### 절 수 검증을 실제로 연결 (오검출 구멍 하나 막음)

`policy.js:93` 에 "그 장에 그 절이 실제로 있는가" 방어 코드가 **이미 있었지만**,
`detect.js` 가 `bibleSource` 를 장 검색(`ChapterSearch`)에만 쓰고 게이트에는 절 수를 넘기지

미뤄둔 상태였다.

실측으로 구멍을 재현했다.

```
"히브리서 1장 33절을 보시죠"   → 히 1:33 [auto]   ← 히브리서 1장은 14절까지
```

`detect.js` 에서 판정 직전에 `verseCount` 를 넘기도록 연결했다.

- 소스가 `verseCount` 를 구현하지 않으면(합성 테스트 스텁) `null` → 검사 자체를 건너뛴다.

- 성경 데이터가 없는 기존 경로(`score.js` 채점)는 `null` 이라 **동작 무변화** → 59/59 유지 확인.

결과: 히 1:33 → `ignore`, 히 1:3 → `auto` 유지, 전체 검증 통과.

### Apple Speech 를 CLI 로 쓰려면 .app 번들이 필수 (막다른 길 2번 겪음)

macOS TCC 때문에 순수 CLI 로는 음성 인식을 못 쓴다. 두 단계로 막혔고 둘 다 크래시 리포트로 확인했다.

1. **맨 실행 파일** → 즉시 SIGABRT(134).
   ```
   namespace TCC — "attempted to access privacy-sensitive data without a usage description.
   The app's Info.plist must contain an NSSpeechRecognitionUsageDescription key"
   ```
2. **실행 파일에 `__TEXT,__info_plist` 섹션 심기** (`-sectcreate`) + 애드혹 서명 → **똑같이 SIGABRT**.
   TCC 는 이 섹션을 인정하지 않는다.
3. **정식 `.app` 번들 + `codesign --deep`** → 번들은 정상(plutil OK, PlistBuddy 로 키 확인)인데
   셸에서 직접 실행하면 **여전히 SIGABRT**. 권한 요청이 부모(셸) 프로세스에 귀속되기 때문.
4. **`open UnoWorshipVoice.app`** (LaunchServices) → **생존 확인**. 앱이 자기 자신의 책임
   프로세스가 되어 통과한다.

그래서 최종 구조는 이렇게 됐다.

```
Node ──spawn('open', [app, '--args', '--out', <파일>])──> .app (자기 책임 프로세스)
     <──── JSONL 파일 증분 추종(fs.watch + 40ms 폴링 보조) ────
```

`open` 으로 띄우면 stdout 이 연결되지 않으므로 결과를 파일로 흘린다. 부수 효과로 이 파일이
**블랙박스 로그(PLAN 11절)** 를 그대로 만족한다. 파일 전달 지연은 실측에서 무시할 수준.

### 권한 두 고비 (둘 다 해결)

1. **받아쓰기가 꺼져 있으면 음성인식 권한이 자동 거부된다.** 켠 뒤에도 TCC 에 "거부"가
   남아 다시 묻지 않는다. 우리 앱 것만 초기화해야 프롬프트가 되살아난다.
   ```bash
   tccutil reset SpeechRecognition com.unoworship.voice.stt
   tccutil reset Microphone com.unoworship.voice.stt
   ```
2. **권한 창이 안 뜨고 독에서 아이콘만 튀는 문제.** 번들만 갖추고 `RunLoop.main.run()` 으로
   돌면 앱이 "실행 중" 상태에 머물러 프롬프트를 표시하지 못한다.
   `Info.plist` 에 `LSUIElement=true` 를 넣고 `NSApplication.shared` 를 `.accessory` 정책으로
   `run()` 하도록 바꿔서 해결했다 (독 아이콘 없는 백그라운드 앱).

### 입력 장치는 앱이 직접 고른다 (시스템 설정 불가침)

이 맥은 예배 운영 기계라 사운드 기본 입력/출력을 함부로 바꾸지 않는다. 그래서 CoreAudio 로
장치를 열거하고 `kAudioOutputUnitProperty_CurrentDevice` 로 **이 앱의 입력만** 교체한다.

```bash
--list-devices          # 입력 가능한 장치 나열
--device BlackHole      # 이름 일부만 맞으면 됨
```

현장 전환 시 `--device M32` 로 바꾸기만 하면 된다.

### 남은 차단 요인: 시스템 받아쓰기 꺼짐 (해결됨 — 위 참조)

`ready` 까지는 정상(온디바이스 true, 48kHz)인데 인식 태스크가
`kLSRErrorDomain(201) Siri and Dictation are disabled` 로 실패한다.
받아쓰기가 꺼져 있으면 음성 인식 권한 요청도 **자동 거부(상태 1)** 된다.

## 2026-07-28 — 실제 음성 첫 검증 (유튜브 설교)

검증 소재: **2026-07-26 주일2부(한만상 목사, 요13:31-38)** — 사고 당일 설교이자

### 파이프라인은 실제 음성으로 끝까지 동작했다

한국어 인식 품질 자체는 좋았다. 예: "하나님의 사랑이 우리에게 이렇게 나타나게 되었으니
하나님이 자기의 독생자를 세상에 보내신 것은…" (요일 4:9 낭독) — 거의 정확.

**자기정정 케이스를 정확히 처리했다.** 정답지 36:07.
```
STT 원문: "…더 큰 은사 인 사랑에 대해서는 요한복음 고린도 13 장 한장"
결과    : 고린도전서 13장 [hold] conf 0.85     ← 요한복음(오늘 본문)에 낚이지 않음
```

### ⚠️ 발견 1 — Apple Speech 는 장·절을 한글 수사로 쓴다 (전제가 깨짐)

`spokenAdapter.js:84` 의 전제 **"실제 STT(유튜브·Whisper·Apple)는 장·절 번호를 아라비아
숫자로 출력한다"** 가 Apple Speech 에서는 **거짓**이었다.

```
정답    롬 5:8 (35:04)
STT 원문 "그래서 로마 스 오장 팔 절에는 우리가 아직 죄인 되었을 때…"
결과    미검출
```

픽스처(유튜브 자동자막)는 숫자로 나와서 59/59 가 나왔던 것 — **엔진이 바뀌면 전제가 바뀐다.**
2단계(실환경 검증)를 하지 않았으면 못 잡았을 문제다.

### ⚠️ 발견 2 — 한글 수사만 고치면 곧바로 오검출이 터진다

띄어쓰기 오인식이 겹쳐 있다.

```
"로마 스 5장 8절"  →  에스라 5:8      ← "스"가 에스라 약칭과 매칭 (오검출!)
"로마 스 오장 팔 절" →  (없음)         ← 지금은 한글 수사 때문에 가려져 있을 뿐
```

즉 **한글 수사 지원을 켜는 순간 "로마서"가 "에스라"로 송출된다.** 두 문제는 반드시 함께 다뤄야 한다.

### 한글 수사를 되살릴 때의 제약 (기존 결정 존중)

미지원은 실수가 아니라 근거 있는 결정이었다 (`spokenAdapter.js:77-85`).
```
"대제사장"  → 사(4) + 장 → 4장
"성경 구절"  → 구(9) + 절 → 9절
```
그래서 단순 치환은 금지. 안전한 방향은 **"인식된 책 이름 바로 뒤"에서만 수사를 변환**하는 것이다.
- `로마서 오장 팔절` → 책 매칭 성공 → 변환 ✅
- `성경 구절` · `대제사장` → 앞에 책 이름 없음 → 변환 안 함 ✅ (오검출 방지)

`로마 스` 같은 띄어쓰기 오인식은 별도로, 공백을 접은 형태로도 `fuzzyBook` 을 시도하면
`로마스 → 로마서`(자모 편집거리 1)로 잡힌다. **1글자 별칭은 위험도가 높아 강화 필요.**

### 지연 측정 버그 (고침)

부분결과에는 애플이 구간 타임스탬프를 안 채워 `audioEnd` 가 전부 0 이었고, 그 결과
지연이 140초로 찍히고 감지기에도 시각 0 이 들어가 중복 억제·문맥 만료가 오작동했다.
탭에서 넣은 오디오 총량(`audioFed`)을 폴백으로 쓰도록 고쳤다. 재측정 필요.

### 한글 수사 되살리기 — 기존 결정을 뒤집되 근거를 지켰다

미지원은 근거 있는 결정이었으나(일상어 충돌), 그 전제("Apple 도 숫자로 출력한다")가 실측으로
깨졌다. 그래서 **전면 허용이 아니라 조건부**로 되살렸다. 파서 본체는 안 건드리고 전처리 2단계만 추가.

1. `repairBookSpacing` — 공백으로 끊긴 책 이름 복구. 자모 편집거리 1 이내 + 뒤에 장/절 표지가
   있을 때만. `"로마 스" → "로마서"`. 이게 없으면 1글자 별칭 `스`(에스라)가 먹어서 **오검출**이 난다.
2. `convertSinoNumerals` — **2글자 이상 책 별칭이 나온 지점부터 40자 이내**에서만 한글 수사를
   숫자로 바꾼다. 추가로 `장/절` 뒤가 조사·경계여야 한다(`"사장님"`의 `님`은 불가).

```
로마서 오장 팔절            → rom 5:8        ✅
로마 스 오장 팔 절에는       → rom 5:8        ✅  (실측 발화)
시편 백십구편 백칠십육절      → psa 119:176    ✅
대제사장이 · 성경 구절을      → 없음           ✅  (앞에 책 이름 없음)
우리 회사 사장님이           → 없음           ✅
```

회귀 기준을 그대로 통과했다 — **단위 31개(신규 7) · 설교 59/59 · 오검출 0건.**
새 케이스는 `tests/spokenNumerals.test.mjs` 로 고정했다.

### 운영 범위 확정 (사용자, 2026-07-28)

**말씀찾기(인용) 프로그램에만 적용한다.** 본문은 기존 말씀찾기(본문) 숨김 프로그램이
절 번호 = 섹션 번호로 담당하므로 음성이 개입할 필요가 없다.

이 범위 제한이 안전성을 크게 올린다.
- 음성이 건드릴 수 있는 대상이 한 프로그램의 섹션으로 **한정**된다. 찬송·사도신경·설교대지는 절대 안 바뀐다
- 인용 목록이 미리 오므로 **후보 집합이 닫혀 있다** — 닫힌 후보군은 속도와 정확도를 함께 올린다
- 인용구절은 **절 범위까지** 제공된다(사용자 확인). 본문과 절 번호가 겹쳐도 정확히 구분 가능

선행 감지 동작도 코드로 확인했다.
```
"마태복음"        → —                       (숫자 없어 확정 안 함)
"마태복음 22장"    → 🟡 마태복음 22장 0.85     ← 후보 확정 + 장 검색 무장 + 문맥 갱신
"…22장 37절…"    → 🔵 마태복음 22:37 1.00
"38절을 보시죠"    → 마태복음 22:38           (문맥 추적)
"본문 36절을…"    → 요한복음 13:36           ('본문' 키워드가 문맥보다 우선)
```
