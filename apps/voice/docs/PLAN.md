> **현재 방식은 담당자의 숙련도 문제가 아니라, 물리적으로 불가능한 업무 설계다.**

| 입력 | 현재 | 비고 |
|---|---|---|
| `시편136장21-26절` | ✅ | `.replace(/장(?=\d)/g, ':')` |
| `요한복음 13장 31절` | ⚠️ | **장 뒤 공백** 미처리 |
| `31절에서 38절까지` | ❌ | 구어체 범위 |
| `6절에` | ❌ | 조사 + 문맥 의존 |

→ **구어체 전처리 어댑터**를 앞단에 추가한다. 파서 본체는 수정하지 않는다.

## 4. 운영 모델 — 자율주행

### 비유

```
설교 시작 → [음성송출 버튼] → 자율주행 ON
                              사람은 감시만
                              문제 있을 때만 개입
```

담당자는 카메라 3대를 주요 앵글로 고정해 두고, 강대상을 벗어날 때만 컷을 누른다.
손은 대체로 자유롭지만, **평상시 아무것도 누르지 않아도 굴러가야 한다.**

### 선송출 후정정 (rev.2 변경 핵심)

실측 여유가 0.51초인데, 확정에 필요한 시간은 숫자키로도 약 0.55초다.

```
확정에 필요한 시간(숫자키)  0.55초
실제 주어진 여유            0.51초
                          ─────────
                          이미 초과
```

> **"물어보고 허가받는" 구조는 이 속도에서 성립하지 않는다.**
> 자율주행차는 차선 변경 허가를 묻지 않는다. 스스로 하고, 사람이 개입한다.

| | 순서 | 시간 압박 | 사람 역할 |
|---|---|---|---|
| ~~rev.1~~ | 후보 제시 → 확정 → 송출 | 0.5초 안에 | 허가자 |
| **rev.2** | **송출 → 필요시 정정** | **없음** | **감시자** |

### 조작 규격

| 키 | 동작 |
|---|---|
| `1` `2` `3` | 후보 교체 |
| `0` 또는 `ESC` | 취소 (직전 자동 송출 되돌리기) |
| 토글 버튼 | 자율주행 ON/OFF |

## 5. 설계 원칙

### 원칙 1 — 완전 분리

음성 모듈은 **독립 프로세스**로 동작한다.

> **음성 모듈이 죽어도 수동 송출은 100% 정상 동작해야 한다.**
> 실험적 기능 때문에 자막 전체가 멈추면 기존 사고보다 더 큰 사고다.

하트비트가 2초 이상 끊기면 컴포저가 자동으로 수동 모드로 전환한다.

### 원칙 2 — 오검출 0건이 검출률보다 우선

자막이 안 나오면 담당자가 메울 수 있지만, **틀린 자막은 예배 흐름을 깬다.**
애매하면 송출하지 않고 조용히 로그만 남긴다.

### 원칙 3 — 교회 가기 전에 검증 완료

2026-07-26 설교 오디오 + 정답지 29건을 회귀 테스트 픽스처로 사용한다.
녹음 재생으로 정확도·지연을 PC에서 전부 측정할 수 있다.

## 7. 이벤트 규격

기존 `SocketMessage` 유니온에 **음성 전용 타입만 추가**한다. 기존 타입은 건드리지 않는다.

```ts
// lib/socketEvents.ts 에 추가
| { type: 'VOICE_DETECTED'; payload: {
      seq: number;
      ref: { bookId: string; chapter: number; verses: number[] };
      display: string;          // "요한일서 5:3"
      confidence: number;       // 0.0 ~ 1.0
      action: 'auto' | 'hold';  // hold = 송출 안 함, 알림만
      raw: string;              // STT 원문 "요한일서 5장 3절에"
      latencyMs: number;        // 발화 종료 → 발행
      candidates: Array<{ display: string; ref: object; confidence: number }>;
  } }
| { type: 'VOICE_CORRECTED'; payload: { seq: number; ref: object; display: string } }
| { type: 'VOICE_STATE'; payload: { state: 'idle'|'armed'|'preaching'; engine: string } }
| { type: 'VOICE_HEARTBEAT'; payload: { ts: number; audioLevel: number } }
```

`VOICE_DETECTED` 를 받은 컴포저는 기존 송출 경로(`SUBTITLE_UPDATE` 등)를 그대로 호출한다.
**음성 모듈은 화면을 그리는 방법을 몰라도 된다.**

## 9. 파서 사양 (기존 재사용 + 어댑터)

### 9.1 구어체 전처리 어댑터 (신규)

```
"요한복음 13장 31절에서 38절까지"  →  "요한복음 13:31-38"
"6절에"                          →  (문맥) "로마서 5:6"
"삼십육절"                        →  "36절"   (한글 수사 대비)
```

### 9.2 문맥 추적 (신규)

"현재 책·장" 상태를 유지한다. **어제만 4건 발생한 유형이다.**

| 실측 | 발화 | 해석 |
|---|---|---|
| 35:04 | "로마서 5장 8절" | 문맥 = 롬 5장 |
| 35:34 | "**6절**에" | → **롬 5:6** |

사람이 가장 자주 놓치는 지점이자, 기계가 가장 잘하는 지점이다.

### 9.3 범위 검증 (신규)

```
본문이 요 13:31–38일 때
  "36절" → 요 13:36  ✅
  "3절"  → 범위 밖 → 오인식 의심 → 송출 안 함
```

닫힌 후보군은 속도만이 아니라 정확도도 올린다.

## 10. 게이트 사양

### 10.1 자기정정 대기 — 실측 함정

36:07 실측 발화:

```
"요한복음 … 아, 고린도서 13장"
```

요한복음은 **오늘 본문**이라 성급히 반응하면 엉뚱한 화면이 뜬다.
→ 송출 후에도 **1.5초간 감시**. 새 책 이름이 나오면 `VOICE_CORRECTED`로 조용히 교체.

### 10.2 신호 표현 판별

| 발화 | 판정 |
|---|---|
| "36절을 **보시죠**" / "**한번 볼까요**" / "**읽겠습니다**" | 송출 ✅ |
| "36절은 **나중에**" | 무시 ❌ |
| "35절과 36절 **사이에**" | 보류 (알림만) ⚠️ |

### 10.3 판정 정책 (초기값 — 검증 후 조정)

| 조건 | action |
|---|---|
| 책·장·절 완전 + 인용목록 존재 + conf ≥ 0.85 | `auto` |
| 본문 범위 내 절 번호 + 신호 표현 | `auto` |
| 그 외 conf ≥ 0.6 | `hold` (알림만, 숫자키로 확정) |
| 범위 밖 / 목록에 없음 / conf < 0.6 | 무시 (로그만) |

## 11. 블랙박스 (운영 리포트)

자율주행에 주행기록계가 필수이듯, 모든 판단을 기록한다.

| 기록 | 용도 |
|---|---|
| 감지 성공 (ref, conf, 지연) | 주간 정확도 추이 |
| 보류/무시 (raw 원문 포함) | 임계값 조정 근거 |
| 사람 정정 (무엇→무엇) | **오답 학습 데이터** |
| 미감지 (사후 대조) | 검출률 |

예배 후 한 장짜리 리포트로 출력한다. **이게 있어야 매주 정확도가 올라간다.**

## 12. STT 엔진 — 두 후보 실측 비교

M4 24GB에서 둘 다 실행 가능하므로 **픽스처로 비교 후 결정**한다.

| | whisper.cpp (large-v3-turbo) | Apple Speech (온디바이스) |
|---|---|---|
| 지연 | 0.4~0.8초 | **0.2~0.4초** |
| 한국어 정확도 | **높음** | 중간 |
| 스트리밍 | 슬라이딩 윈도우 필요 | **네이티브 부분결과** |
| 어휘 힌트 | 프롬프트 주입 | `contextualStrings` |
| 네트워크 | 불필요 | 불필요 |

필요한 건 책·장·절뿐이므로 전체 정확도보다 **참조 인식률과 지연**이 중요하다.

### 지연 예산 (목표)

```
오디오 버퍼          20~50ms
STT 부분결과        200~500ms
어댑터+파서+게이트    < 10ms
Socket.IO 전송      < 5ms
캔버스 렌더          16~30ms
──────────────────────────
합계                0.25 ~ 0.6초
```

**선행 감지**: "요한복음 13장"까지만 들어도 후보가 좁혀지므로, 발화 도중 준비가 끝난다.
