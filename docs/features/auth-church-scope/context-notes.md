# 로그인 · 교회 스코프 · 팀 권한

작성일 2026-08-09

## 왜 지금 하는가

입력웹 세 기능(헵시바 선교단 · 설교대지 · 준비찬양)이 거의 다 붙었다.
다음은 교회별 구독으로 나가는 것인데, 지금은 **배포 한 벌이 교회 하나**다.

```ts
// lib/churchScope.ts — 지금
const slug = (process.env.UNOWORSHIP_DEFAULT_CHURCH_SLUG || 'ulju').trim();
let cached: { slug, id, name } | null = null;   // 모듈 수준 캐시
```

환경변수에 교회가 박혀 있고, 모듈 수준 변수에 캐시해 요청 사이에 공유된다.
로그인을 붙여도 이걸 바꾸지 않으면 아무 것도 갈리지 않는다.

그리고 **쓰기 라우트에 인증 강제가 없다.** 지금은 URL 만 알면 저장된다.

## 로그인 수단 — 카카오

대상이 찬양팀원·반주자이고 거의 모바일이라 이메일 가입은 이탈이 크다.
Supabase Auth 가 카카오를 기본 제공자로 지원하므로 새로 만들 것은 없다.

**카카오에서 받는 것은 닉네임·프로필사진까지만.** 이메일·성별·연령대 같은 항목은
비즈 앱 전환을 요구하므로 받지 않는다. 구독 결제를 붙일 때 사업자 등록과 함께 다시 본다.

**이메일+비밀번호 로그인은 남겨 둔다** — 카톡 없는 분, PC 로만 쓰는 목회자, 개발·테스트용.

### 이름을 따로 받아야 하는 이유

카톡 닉네임은 `🌸행복🌸`, `ㅁㅁ`, `아빠` 같은 경우가 흔하다. 관리자 화면에 그 목록이
뜨면 누가 누구인지 알 수 없어 팀장 교체도 못 한다. 그래서 **가입 직후 '교회에서 부르는
이름'을 한 번 받는다.** 카카오에서 받는 게 아니라 우리가 묻는 것이라 비즈전환과 무관하다.

```
카카오 로그인 → (처음이면) 이름 입력 → 코드 입력 → 교회·팀 확정
```

## 누가 무엇을 할 수 있는가

| 역할 | 어떻게 되는가 | 무엇을 하는가 |
|---|---|---|
| 교회 관리자 | 그 교회 **첫 사용자** | 모든 팀 수정·삭제, 코드 발급, 팀장 교체 |
| 팀장 | **1회용 팀장 코드**를 쓴 사람 | 그 팀의 곡·악보 수정·삭제 |
| 팀원 | 교회 코드로 참여 후 팀을 고른다 | 보기만 |

### 코드는 두 종류다

```
교회 참여 코드   교회당 1개. 여러 번 쓴다. 단톡방에 뿌려도 된다
팀장 코드        (교회·팀)당 1개. 1회용 — 쓰는 순간 소진된다
```

**왜 '처음 들어온 사람이 팀장'으로 하지 않는가** — 코드는 십중팔구 단톡방에 뿌려진다.
팀장에게 1:1 로 보내도 팀장이 그대로 복사해 팀원들에게 돌린다. 그러면 먼저 누른
사람이 팀장이 되고 다른 사람까지 세울 수 있다. 팀장 자리만 1회용으로 닫아 두면
코드가 돌아다녀도 사고가 나지 않는다.

**교회 관리자는 첫 사용자로 둔다.** 구독을 결제한 사람이 가장 먼저 들어오므로
엉뚱한 사람이 될 위험이 거의 없다. 위험한 것은 팀 단위뿐이다.

**팀원은 코드를 따로 두지 않는다.** 교회 코드 하나로 들어와 팀을 직접 고른다.
코드가 팀 4개 × 2 = 8개에서 2개로 준다. 팀을 잘못 골라도 보기 권한뿐이라 피해가 없고
팀장이 나중에 정리하면 된다.

**관리자는 언제든 팀장을 교체할 수 있어야 한다.** 사람이 바뀌고, 그만두고, 사고도 난다.

## 권한의 '팀'은 찬양팀이 아니라 기능이다 (2026-08-09 정정)

처음에는 권한 단위를 찬양팀(주일1부·2부·수요·금요)으로 잡았다. 틀렸다.
실제로는 **기능마다 담당자가 다르다.**

```ts
const TEAMS = ['설교대지', '준비찬양', '찬양대'];
```

설교대지는 목회자·비서가, 준비찬양은 찬양 인도자가, 찬양대는 헵시바 담당이 맡는다.
한 사람이 그 기능 전체를 본다.

**준비찬양 안의 주일1부·2부·수요·금요는 그대로 둔다.** 그건 자료를 나누는 분류이지
권한 단위가 아니다 — 준비찬양 담당자 한 사람이 네 팀의 곡을 다 관리한다.

코드 표의 `team` 이 문자열이라 목록만 바꿔서 넘어갔다.

## 팀 이름은 아직 데이터로 빼지 않는다

교회마다 팀 이름이 다르므로 제품화 시점에는 결국 빼야 한다. 그러나 지금 빼면
화면·API·라이브러리의 문자열 `team` 을 전부 갈아야 해서 작업이 몇 배가 된다.
**두 번째 교회가 들어올 때** 한다. 그때도 아래 권한 표는 그대로 살아남는다.

## 한 사람이 여러 팀에 속할 수 있다

반주자가 1부와 수요예배를 같이 하는 경우가 흔하다. 그래서 팀 소속은
`church_members`(교회당 1행)가 아니라 별도 표에 (교회·사용자·팀) 단위로 둔다.

## 단계와 순서

```
1. 교회 스코프   getActiveChurchId() 를 로그인 사용자 → 소속 교회로. 모듈 캐시 제거
2. 인증 강제     쓰기 라우트에 로그인 요구. 현장 맥은 이미 있는 디바이스 토큰으로
3. 카카오 로그인 Supabase 제공자 설정 + 버튼 + 이름·코드 받기
4. 팀 권한       팀장만 수정·삭제. 화면 잠금
```

**1단계에서 폴백을 남긴다.** 세션이 없으면 기존 환경변수 교회로 떨어진다.
그러지 않으면 현장 맥(UnoLive)의 읽기 호출과 지금 쓰는 화면이 한꺼번에 멈춘다.
폴백은 3단계까지 유지하고 마지막에 걷는다.

## 카카오 동의항목은 Supabase 기본 스코프에 맞춰야 한다 (2026-08-09)

카카오 로그인이 `KOE205`(잘못된 요청)로 막혔다. 실제로 나가는 스코프를 열어 보니
이랬다.

```
scope = account_email profile_image profile_nickname profile_nickname
```

**Supabase 는 자기 기본 스코프에 우리 것을 덧붙인다.** 덮어쓰지 않는다
(`profile_nickname` 이 두 번 들어간 것이 그 증거다). 그래서
`signInWithOAuth({ options: { scopes } })` 로 `account_email` 을 뺄 수 없다 —
한 번 그렇게 고쳤다가 되돌렸다.

Supabase 대시보드에도 카카오 스코프를 지우는 칸이 없다. 결국 **카카오 쪽 동의항목을
Supabase 가 요청하는 것에 맞추는 수밖에 없다.**

| 항목 | 설정 | 왜 |
|---|---|---|
| 닉네임 | 필수 동의 | 화면에 이름을 깔아 주는 용도 |
| 프로필 사진 | **선택 동의** | Supabase 가 항상 요청한다. '사용 안함' 이면 KOE205 |
| 카카오계정(이메일) | **선택 동의** | 같은 이유. 필수 동의로 하면 비즈 앱 전환을 요구한다 |

**선택 동의로 두면 비즈 앱 없이도 요청은 통과한다.** 사용자가 거절하면 이메일이 안 오고,
그건 Supabase 의 `Allow users without an email` 이 받아 준다 — 우리는 어차피 이메일을
쓰지 않는다.

## 권한은 두 갈래뿐이다 (2026-08-09 정정 2)

카테고리 담당(준비찬양 전체를 보는 사람)을 두려다 접었다. 교회 관리자와 역할이 겹쳐
'누가 무엇을 할 수 있나'가 세 갈래가 된다. 실제로 총괄하는 사람이 있다면 그를 관리자로
두거나 여러 팀 담당으로 지정하면 된다.

```
교회 관리자   전부
팀 담당       그 팀만
설교대지      작성자 본인
그 외         보기만
```

**설교대지는 팀이 아니라 개인이다.** 담임목사도 부교역자도 각자 자기 설교대지를 쓴다.
그래서 담당자 코드가 없다 — 로그인만 하면 자기 것을 만들고, 남의 것은 못 고친다.
조회는 열어 둔다(현장 맥과 방송실이 그 예배의 것을 가져가야 한다).
`sermon_outlines.created_by` 가 이미 있으니 채우기만 하면 된다.

**참여 화면에서 담당 선택 칸을 뺐다.** 팀원은 보기만 하므로 팀 소속이 아무 역할을 하지
않는다. 팀 소속은 담당자에게만 생기고 그것은 담당자 코드가 정한다. 첫 참여자(구독을
결제한 관리자)에게 '담당을 고르라'고 묻는 것도 어색했다.

카테고리는 화면을 나누는 이름일 뿐 권한 축이 아니다. 그래서 팀 목록은 카테고리를
가로질러 평평하다 — 주일1부·2부·수요예배·금요기도회(준비찬양) + 헵시바(찬양대).

## 팀을 데이터로 뺀다 (2026-08-09 정정 3)

교회마다 팀 이름이 다르다. 울주교회는 준비찬양이 주일1부·2부·수요예배·금요기도회이고
찬양대가 헵시바인데, 다른 교회는 시온찬양대·호산나찬양대일 수 있다. 화면에 목록을
박아 두면 두 번째 교회에서 바로 무너진다.

```
관리자가 팀을 만든다      이름 + 카테고리(준비찬양 / 찬양대)
팀원은 자유로이 가입       코드 없이 목록에서 고른다. 복수 팀 가능
담당자는 코드로 정한다     1회용 담당자 코드
안 들어온 팀은 안 보인다   가림막이지 잠금이 아니다
설교대지는 팀이 없다       각자 자기 것
```

**가입을 자유로 두는 이유** — 팀 경계는 '자기 팀 것만 보이게 해서 화면을 단순하게' 하는
장치다. 교회 안에서 훔쳐볼 사람을 막는 것이 아니다. 한 사람이 여러 팀에 드는 것도 흔하다
(반주자가 1부와 수요예배를 같이 한다).

**이름을 키로 쓴다.** `worship_prep_songs.team` 등이 이미 이름 문자열을 물고 있어서
team_id 로 바꾸면 쌓인 자료를 전부 옮겨야 한다. `worship_teams` 에 (교회·이름) 고유
인덱스를 걸어 이름이 곧 키가 되게 했다.

**팀을 지우지 않고 접는다**(`archived_at`). 지우면 그 팀 이름을 물고 있는 자료가 미아가 된다.

**담당자는 스스로 팀을 나갈 수 없다.** 나가면 그 팀에 담당자가 없어지는데 담당자 코드는
1회용이라 관리자가 새로 뽑아야 한다. 관리자를 거치게 한다.
